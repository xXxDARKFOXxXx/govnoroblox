SKYBRICK — НЕБЕСНЫЙ ЛАКИ-БЛОК
Золотой конструкторный блок с объёмными ангельскими крыльями.
Создан по предоставленному референсу; без сторонних моделей и логотипов.

НОВАЯ АДАПТАЦИЯ ПРИСЛАННОЙ АНИМАЦИИ
Используй Roblox_Opening_Animation_Adapted.txt и ANIMATION_ADAPTED_RU.md.
Замени содержимое старого Opening Script; не запускай оба варианта вместе.
Ниже описан первоначальный демонстрационный вариант Roblox_Opening_Animation.txt.

ФАЙЛЫ
Skybrick_Lucky_Block.fbx     — основной файл для импорта в Roblox Studio.
Skybrick_Lucky_Block.glb     — альтернативный формат с PBR-материалами.
Skybrick_Atlas.png           — единая текстура 1024 × 1024 для всех деталей.
Skybrick_Lucky_Block.blend   — редактируемый исходник Blender 4.3.2.
Preview.png                 — реальный рендер модели из Blender.
Roblox_Opening_Animation.txt — код Luau, который нужно вставить в Script.
build_lucky_block.py         — воспроизводимая генерация модели для Blender.
model_info.json              — статистика экспортированной геометрии.
VALIDATION.txt               — результаты выполненных проверок.

ИМПОРТ В ROBLOX STUDIO
1. Открой свою игру. Через Import 3D выбери Skybrick_Lucky_Block.fbx.
   Название и расположение кнопки зависят от версии Studio.
2. Сохрани отдельные объекты; не объединяй всю модель в одну сетку.
   Импортируй корпус, крышку и два крыла вместе, с исходным расположением.
   При наличии опции вставки сцены/модели используй её.
3. В Explorer должна получиться структура:

   SkybrickLuckyBlock (Model)
     Body  (MeshPart)
     Lid   (MeshPart)
     WingL (MeshPart, крыло слева по локальной оси X)
     WingR (MeshPart, крыло справа по локальной оси X)
     Opening (обычный Script, не LocalScript)

   Если импортёр добавил суффиксы к именам, переименуй четыре сетки точно
   как указано выше. Если он разделил сетку по материалам, собери её части
   в Model или Folder с соответствующим именем Body/Lid/WingL/WingR.
   Эти четыре группы должны быть непосредственными детьми общей Model.
   Не добавляй WeldConstraint/Motor6D: скрипт двигает закреплённые детали.
4. Текстура встроена в FBX, а PNG приложена отдельно. Если импортёр её
   не подхватил, импортируй Skybrick_Atlas.png как изображение и укажи её
   asset ID в TextureID каждой из четырёх MeshPart. Если используется
   SurfaceAppearance, назначь этот atlas в ColorMap вместо TextureID.
   Не используй одновременно SurfaceAppearance с другим ColorMap.
   Оставь цвет MeshPart белым, чтобы не затонировать готовую текстуру.
   Рекомендуемый Material: SmoothPlastic. Металличность FBX может отличаться
   от рендера Blender; GLB лучше сохраняет PBR-материалы.
5. Сделай корпус примерно 3–4 studs в высоту. Масштабируй общую модель,
   а не отдельные сетки. Установи блок вертикально и над поверхностью.
   Скрипт учитывает единый масштаб, положение и поворот общей модели.
6. Создай внутри Model обычный Script с именем Opening. Удали стандартную
   строку и вставь ВСЁ содержимое Roblox_Opening_Animation.txt. Оставь
   RunContext = Legacy (или Server), Disabled = false. Храни модель
   в Workspace, чтобы серверный Script запускался.
7. Нажми Play, подойди к блоку и удержи E. На мобильном устройстве
   используется экранная кнопка ProximityPrompt, на геймпаде — X.

ЧТО ПРОИСХОДИТ ПРИ ОТКРЫТИИ
Лёгкое парение в ожидании → сжатие и дрожание → подъём блока → взмах
крыльев и отрыв крышки → золотые и бирюзовые искры, вспышка, расходящееся
неоновое кольцо и разлетающиеся маленькие кирпичики → закрытие и сброс.
Эффект виден игрокам через сервер. Одновременное повторное открытие
блокируется; временные объекты удаляются автоматически. Детали блока
закреплены и не имеют коллизии. Это декоративный интерактивный объект.
Встроенные текстуры частиц Roblox не требуют загрузки своего изображения.
При необходимости отключи парение строкой local IDLE = false в скрипте.

НАГРАДЫ И ЗВУК
Скрипт не выдаёт валюту/предметы и не содержит чужих аудио-ID.
При вспышке вызывается BindableEvent Opened внутри модели с аргументом
player. Свой серверный обработчик наград можно подключить к этому событию.
Opened — серверное событие, не RemoteEvent. Для наград добавь правила
своей игры: лимиты, сохранение данных и проверку возможности получения.

BLENDER
Открой .blend. Четыре игровые сетки называются Body, Lid, WingL, WingR.
Объекты STUDIO_* — только камера, свет и пол для рендера; их нет в FBX/GLB.
На таймлайне 1–108 есть демонстрация механического открытия, 30 fps.
Нажми Space для просмотра. Частицы и световое кольцо реализованы в Luau;
не ожидай их при воспроизведении Blender-таймлайна или в самом FBX.
FBX/GLB экспортированы в закрытой позе; анимация не запечена в экспорт.
Для самостоятельного изменения формы выбери сетку и используй Edit Mode.

ПОВТОРНАЯ ГЕНЕРАЦИЯ
Скрипт очищает текущую сцену: запускай только в новом пустом файле Blender!
В терминале (Blender 4.3+):
blender -b --python build_lucky_block.py -- /полный/путь/к/новой/папке
Зависимостей, кроме Blender и поставляемого с ним NumPy, нет.
При отсутствии Blender в PATH укажи полный путь к исполняемому файлу.

ПРОВЕРКА В STUDIO
Запусти Play и проверь: E появляется рядом с блоком; крылья и крышка
двигаются отдельно; частицы видны; повторный запуск работает после сброса.
Посмотри Output на ошибки. Для сетевой игры проверь через Start Server
с двумя игроками, что эффект виден обоим и нельзя открыть блок дважды
одновременно. Сам Roblox Studio в этой среде не запускался: поведение
его импортёра, отображение материалов и Luau требуют этой проверки.
